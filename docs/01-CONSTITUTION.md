## 1. 项目使命

### 1.1 一句话使命

**面向飞书 AI 校园挑战赛题二，以"决策原子 + 演化谱系"为核心单元，在 17 天周期内构建可跑通的企业级长程记忆引擎，并通过三大主测试自证价值。**

### 1.2 选定方向

- **主方向**：方向 B（项目决策与上下文记忆）
- **自然覆盖**：方向 D（遗忘曲线）由五维自适应遗忘机制承载
- **明确不做**：方向 A（CLI 高频命令补全）、方向 C（个人偏好隐式学习）

### 1.3 核心立场（不可撼动）

企业级记忆的核心矛盾是 **多人多源决策的演化与一致性**，不是个人命令历史的统计补全（后者已被 fish/atuin/zsh-autosuggestions 解决）。

把有限的工程预算与答辩篇幅集中在决策一致性这一命题上，是宪法级取舍。任何"顺手做一下方向 A 自动补全也挺酷"之类的范围漂移 —— 一律拒绝。

## 2. 记忆的定义（挑战一答案）

### 2.1 定义

> **企业级记忆 = 带演化谱系、跨源共识度、五维时效衰减的决策原子集合。**

### 2.2 决策原子的七字段约束

```
(subject, predicate, object, timestamp, provenance, confidence, evolution_link)
```

任何字段缺失的对象 **不被认定为决策原子**，不进入记忆引擎主路径。允许进入辅助来源队列，但不计入记忆总量、不参与三大主测试。

### 2.3 四属性硬约束（缺一不可）

| # | 属性 | 检验问题 |
|:---|:---|:---|
| 1 | 可时序对比 | 能回答"这条决策何时被推翻？" |
| 2 | 可覆盖追踪 | 能表达 SUPERSEDES / REFINES / BRANCHES / GENERALIZES 四类关系 |
| 3 | 可跨源对齐 | 能判定群聊/OKR/文档说的是不是同一件事 |
| 4 | 可机器执行 | 能让 CLI 基于这条决策做拦截或补全 |

不满足以上四属性的对象（如自由文本、命令日志、会议录音原始流），可作为 **辅助来源** 接入，但不作为记忆最小单元。

## 3. 范围边界

### 3.1 In Scope（必做，未交付即"未达完成"）

#### 3.1.1 七大核心机制（与 DESIGN.md §四 完整对齐）

| 编号 | 机制 | 关键产出 |
|:---|:---|:---|
| M1 | 全源跨系统一致性检测 | 六档 provenance 信任权重 + 共识度计算 |
| M2 | 演化图谱 | LLM 主路径 + OPPOSITE_PAIRS 词表加速层 |
| M3 | Reflect 自改进循环 | 仅边界置信度 [0.5, 0.85] 触发 |
| M4 | Actor-Aware 六档溯源 | USER_STATED → SYSTEM_INFERRED 信任分级 |
| M5 | Hot/Cold 双路径 | Hot <200ms 零 LLM；Cold <3s 选择性 LLM |
| M6 | Hard/Soft 卡片分层 + 双闸门 | 打扰预算 5/日 + 工作时间窗 |
| M7 | 五维上下文自适应遗忘 | λ(t) = λ_base × f_freq × f_consensus × f_semantic × f_uncertainty |

#### 3.1.2 三大主测试（赛题强制项）

| 测试 | 协议出处 | 承诺值（见 §8） |
|:---|:---|:---:|
| 抗干扰记忆召回 | DESIGN.md §六.6.1 测试一 | Recall_robust ≥ 90% |
| 矛盾更新覆写 | DESIGN.md §六.6.1 测试二 | Acc_supersede ≥ 95% |
| 操作效能对比 | DESIGN.md §六.6.1 测试三 | E_align ≥ 60× / E_step ≥ 80% |

#### 3.1.3 CLI ↔ 飞书三协议（DESIGN.md §五）

- 协议一：决策下发（飞书 → CLI）
- 协议二：执行拦截（CLI 自检）
- 协议三：验证回写（CLI → 飞书）

#### 3.1.4 三层混合存储

- **结构化存储**（PostgreSQL 16）：全量决策原子 + 演化关系 + ACID + 时效查询 —— v1 单库为底座
- **向量层**：v1 = pgvector（PG 扩展，与决策同库零运维）/ v2 = Qdrant（条件触发，见 §3.3）
- **图层**：v1 = `decisions.parent_id` 自引用 + recursive CTE / v2 = Neo4j Community 或 Kuzu（条件触发，见 §3.3）

### 3.2 Out of Scope（默认不做，禁止悄悄越界）

| 不做的事 | 理由 |
|:---|:---|
| 方向 A 的核心能力（命令前缀补全、参数自动联想） | 已被 fish/atuin/zsh 解决，重复造轮 |
| 方向 C 的核心能力（隐式学习用户偏好、自动化执行） | 与方向 B 主题不一致 |
| 方向 D 的"复习提醒"产品形态 | 已由五维遗忘语义层覆盖，不再做 UI 层提醒 |
| Reflect 的"质量档案 → 自动 Prompt 优化"完整闭环 | 离线再训练超出 17 天预算，保留单次 Reflect |
| 任何依赖梯度训练 / 微调的方案 | Seed-2.0 不开放微调；TPM 1w 不支持训练 |
| 引入 `requirements.txt` 之外的新依赖 | 见 §5.6 |
| 任何"顺手优化"非 ticket 范围内的代码 | 见 CLAUDE.md §1.2 外科手术原则 |

### 3.3 Conditional Scope（条件触发，需 ticket 明确指派）

| 条件项 | v1.0 默认 | 触发条件 |
|:---|:---|:---|
| OKR / 审批 / 妙记 / 日历 四个非主源 API 真实接入 | 用 fixture 模拟 | 主链路（消息+文档+CLI）在 Day 12 前跑通后按余量接入 |
| 本地降级模型（7B 量化版） | 不接入 | Seed-2.0 额度连续 3 日抖动后启用 |
| 多用户 / 多租户支持 | 单租户演示 | 仅在赛后扩展 |
| 离线五维参数自动校准（每两周） | 手工配置 | 仅在 v2.x 演进项中考虑 |
| 向量层切换至独立 Qdrant 服务 | pgvector（PG 扩展） | 单 collection > 1M 向量 OR 近邻 P95 > 200ms |
| 图层切换至 Neo4j / Kuzu | PG 自引用 + recursive CTE | 多跳 ≥ 4 跳频繁出现 OR 多跳 P95 > 500ms |

### 3.4 范围歧义处置

任何 ticket、PR、Claude 响应中若涉及 §3.2 不做项 —— **立即停下**，用一行话指出歧义并请人工裁决。**禁止自行扩张范围**。这是 §6 紧急升级触发条件。

## 5. 工程戒律

### 5.1 接口先于实现

任何模块开发前 **必须**：
1. 检查 `04-ENGUIDE.md §8 接口契约总表`
2. 接口未定义 → 停下要求补契约（不允许"边写边定"）
3. 不允许先写实现再补接口

### 5.2 评测先于功能

任何能力的测试用例必须 **先于** 功能实现存在：
1. `tests/fixtures/` 有对应 fixture
2. `tests/test_*.py` 有对应测试函数（可为 `pass`，但函数必须存在）
3. 实现完后跑测试，必须通过

### 5.3 Schema 一致性

- `schema.sql` 与 `models.py` 必须一一对应
- **改动顺序**：先 SQL → 后 Python → 跑 `validate_consistency.py` → PR 描述写"改了 X 字段，原因 Y"
- 不允许只改一边

### 5.4 LLM 调用透明

- 所有 LLM 调用经由 `utils.light_llm_extract()` / `utils.heavy_llm_extract()`
- 单测必须 mock LLM
- PR 描述必须写"该 PR 在测试中触发了 N 次 LLM 调用"
- **禁止**在 main code path 中调用未经预算控制的 LLM

### 5.5 不变量清单（W1–W15，宪法级）

来自 `DESIGN.md §七`，宪法级化后任何代码、ticket、PR 都不可违反：

| # | 不变量 |
|:---|:---|
| W1 | 任何卡片必须有"忽略"按钮 + 原始来源链接 |
| W2 | REFINES 父节点保持 ACTIVE；SUPERSEDES 父节点转 ARCHIVED |
| W3 | 跨系统冲突告警优先级 > 单系统内冲突 |
| W4 | ARCHIVED 决策可检索但不触发主动告警 |
| W5 | CLI 拦截失败时 **默认放行**，绝不阻塞正常 workflow |
| W6 | Reflect 修改只影响未来提取，不回写已确认历史 |
| W7 | Hot Path 缓存与 Cold Path 存储最终一致性，允许 5 min 延迟 |
| W8 | 自适应遗忘的复议重置必须 **全量清零** |
| W9 | 多源共识度计算中，OKR 权重永远最高 |
| W10 | Soft 高不确定冲突必须走"确认卡片"，禁止直接覆写 |
| W11 | 用户否认过的冲突建议，24 h 内不再重复推送同一决策对 |
| W12 | Seed-2.0 额度耗尽时自动切换本地模型，次日 0 点恢复 |
| W13 | 所有飞书 API 调用必须记录 trace_id |
| W14 | 单用户每日主动卡片推送上限 5 次 |
| W15 | 非工作时段（默认 19:00–9:00）暂停非紧急卡片推送 |

### 5.6 不引入新依赖

`requirements.txt` 已经够用。若需新依赖：
1. PR 描述明文：依赖名 / 用途 / 替代方案
2. 至少一名 active 贡献者（§10.2）✅
3. 默认拒绝

### 5.7 诚实先于自洽

- 实现遇阻 → 直说"做不到 / 阻塞 X"，**不修改测试以让代码通过**
- 发现 Schema/接口/宪法错误 → 在 PR 中明文指出，**不默默改**
- 测试失败 → 先报告原因，再决定改实现还是改测试
- LLM 输出不符合预期 → 不要"调温度直到通过"，先看 prompt 是否清晰

## 6. 紧急升级（Escalation）

遇以下情况，**立即停止编码，等待人工决策**：

1. ticket 与本宪法 / DESIGN / SCHEMA 冲突
2. ticket 描述模糊到无法开始
3. 需要新依赖
4. 需要修改 `schema.sql`
5. 需要跨角色目录改动（见 CLAUDE.md §3.1）
6. 评测无法通过且原因不明
7. LLM 调用次数超过 ticket 预算
8. 发现宪法本身有错或互相矛盾
9. 任何范围漂移嫌疑（§3.4）

**不要试图"自行处理"**。停下来，写 issue 或在响应中明确请求决策。

|:---|:---|:---:|
